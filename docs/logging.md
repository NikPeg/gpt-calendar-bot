# Система логирования

Бот использует гибкую систему логирования с тремя выходами:
- **Консоль** (stdout) - только для ошибок (ERROR+) и startup сообщений
- **Файл** (`./logs/debug.log`) - настраиваемый уровень детализации, полная история
- **Telegram** (ADMIN_CHAT) - настраиваемый уровень детализации, мониторинг в реальном времени

## Где найти логи

### 📁 Файловые логи (рекомендуется)

Полные логи с настраиваемой детализацией находятся в директории `./logs/`:

```bash
# На хост-системе (вне Docker)
./logs/debug.log              # Логи за текущий день
./logs/debug.log.YYYY-MM-DD  # Логи за предыдущий день

# Просмотр в реальном времени
tail -f logs/debug.log
```

**Преимущества:**
- ✅ Полная история диалогов и событий
- ✅ Настраиваемый уровень детализации (INFO, DEBUG, FULL)
- ✅ Автоматическая ротация каждые 24 часа
- ✅ Доступны вне контейнера

### 🐳 Docker logs

Консольный вывод контейнера (только ERROR+ и startup сообщения):

```bash
docker logs -f gpt-calendar-bot
# или
docker-compose logs -f
```

**Использование:**
- Быстрая проверка статуса бота
- Просмотр критических ошибок
- Startup/shutdown сообщения

**⚠️ Ограничение:** В docker logs НЕТ INFO/DEBUG логов - только ERROR и выше

### 💬 Telegram логи

Логи в реальном времени в Telegram чат (настраивается через `TELEGRAM_LOG_LEVEL`):

**Использование:**
- Мониторинг в реальном времени
- Получение уведомлений о проблемах
- Не требует SSH доступа к серверу

## Уровни логирования

Система поддерживает следующие уровни (от менее детального к более детальному):

| Уровень | Значение | Что логируется |
|---------|----------|----------------|
| **DISABLED** | - | Логи отключены полностью |
| **CRITICAL** | 50 | Только критические ошибки |
| **ERROR** | 40 | + Ошибки |
| **WARNING** | 30 | + Предупреждения (блокировки пользователей и т.д.) |
| **MESSAGES** | 25 | Пересылка сообщений пользователей (без текстовых логов INFO) |
| **INFO** | 20 | + Текстовые логи: сообщения пользователей, ответы бота, статистика |
| **DEBUG** | 10 | + Системные промпты (без истории), сырой вывод LLM |
| **FULL** | 5 | + Полные промпты со всей историей диалога |

## Настройка в `.env`

```bash
# Уровень логирования в файл debug.log
# Варианты: DISABLED, CRITICAL, ERROR, WARNING, MESSAGES, INFO, DEBUG, FULL
FILE_LOG_LEVEL=INFO

# Уровень логирования в Telegram чат
# Варианты: DISABLED, CRITICAL, ERROR, WARNING, MESSAGES, INFO, DEBUG, FULL
TELEGRAM_LOG_LEVEL=DISABLED

# ID чата для admin логов
ADMIN_CHAT=123456789
```

## Рекомендуемые конфигурации

### 1. Production - минимальное логирование
```bash
FILE_LOG_LEVEL=WARNING
TELEGRAM_LOG_LEVEL=CRITICAL
```
**Результат:** В файле только предупреждения и ошибки, в Telegram только критические ошибки

### 2. Production - стандартное логирование
```bash
FILE_LOG_LEVEL=INFO
TELEGRAM_LOG_LEVEL=ERROR
```
**Результат:** В файле все важные события, в Telegram только ошибки

### 3. Мониторинг сообщений пользователей в Telegram
```bash
FILE_LOG_LEVEL=INFO
TELEGRAM_LOG_LEVEL=MESSAGES
```
**Результат:** В файле все важные события, в Telegram пересылаются только сообщения пользователей (без текстовых логов INFO) + WARNING/ERROR. Пересылка работает на уровнях MESSAGES, INFO, DEBUG, FULL.

### 4. Разработка - подробное логирование
```bash
FILE_LOG_LEVEL=DEBUG
TELEGRAM_LOG_LEVEL=INFO
```
**Результат:** В файле всё включая системные промпты, в Telegram основные события

### 5. Отладка промптов - максимальное логирование
```bash
FILE_LOG_LEVEL=FULL
TELEGRAM_LOG_LEVEL=DISABLED
```
**Результат:** В файле полные промпты с историей, Telegram отключен

### 6. Без логов (не рекомендуется)
```bash
FILE_LOG_LEVEL=DISABLED
TELEGRAM_LOG_LEVEL=DISABLED
```
**Результат:** Логи полностью отключены (кроме ERROR в консоль)

## Консольный вывод

В консоль (stdout) выводятся только:
1. **Startup сообщения** при запуске бота:
```
==================================================
🤖 БОТ ЗАПУЩЕН
==================================================
Database: Бд подгружена успешно
Debug chat: 123456789
Нажмите Ctrl-C для остановки бота
==================================================
```

2. **ERROR и CRITICAL** логи с полным traceback (для отладки)

3. **Shutdown сообщения** при остановке бота:
```
🛑 Получен сигнал остановки
Останавливаем бота...
✅ Бот остановлен
```

## Telegram логирование

Логи в Telegram отправляются в чат `ADMIN_CHAT` в двух форматах:

### 1. Текстовые логи (уровни INFO, DEBUG, FULL)
```
INFO: USER241248104TOLLM:Привет!
ERROR: LLM241248104 - Критическая ошибка: Connection timeout
WARNING: USER241248104 заблокировал чатбота
```

### 2. Пересылка сообщений (уровни MESSAGES, INFO, DEBUG, FULL)
```
USER241248104
[Пересланное сообщение от пользователя]
```

**Важно:** Пересылка сообщений работает **только** на уровнях MESSAGES (25) и ниже (INFO, DEBUG, FULL). На уровнях WARNING (30) и выше пересылка **отключена**.

| Уровень | Текстовые логи | Пересылка сообщений |
|---------|----------------|---------------------|
| **FULL** | ✅ Все (включая полные промпты) | ✅ Да |
| **DEBUG** | ✅ Все (системные промпты) | ✅ Да |
| **INFO** | ✅ Все основные события | ✅ Да |
| **MESSAGES** | ❌ Нет | ✅ Да |
| **WARNING** | ✅ Только предупреждения | ❌ Нет |
| **ERROR** | ✅ Только ошибки | ❌ Нет |
| **CRITICAL** | ✅ Только критические | ❌ Нет |

**Преимущества:**
- Мониторинг в реальном времени
- Уведомления о проблемах
- Не нужен доступ к серверу

**Рекомендации:**
- Для production с текстовыми логами: `ERROR` или `WARNING`
- Для мониторинга сообщений: `MESSAGES` (без текстовых логов INFO)
- Для разработки: `INFO` (текстовые логи + пересылка)
- Не используйте `DEBUG` или `FULL` в production - слишком много сообщений

## Файловое логирование

Логи сохраняются в директории `logs/` с автоматической ротацией по времени:
- **Ротация:** каждые **24 часа** (в полночь по локальному времени)
- **Хранение:** **2 суток** (текущий день + вчерашний)
- **Кодировка:** UTF-8

### Расположение файлов

**В Docker контейнере:**
- Логи находятся в `/app/logs/`
- Автоматически монтируются в хост-систему через `./logs:/app/logs`

**На хост-системе (вне Docker):**
- `./logs/debug.log` - логи за сегодня
- `./logs/debug.log.YYYY-MM-DD` - логи за предыдущий день (автоматически удаляются через 24 часа)

**Пример:**
```
./logs/
├── debug.log              # Логи за 2025-11-06
└── debug.log.2025-11-05  # Логи за 2025-11-05 (будут удалены в полночь 07.11)
```

### Настройка пути (опционально)

По умолчанию логи записываются в `/app/logs/debug.log`. Вы можете изменить путь через переменную окружения:

```bash
# В .env
LOG_FILE_PATH=/custom/path/to/logs/my_app.log
```

## Полезные команды

### Просмотр файловых логов (на хост-системе)

#### Просмотр в реальном времени
```bash
tail -f logs/debug.log
```

#### Просмотр только ошибок
```bash
grep "ERROR\|CRITICAL" logs/debug.log
```

#### Просмотр логов конкретного пользователя
```bash
grep "241248104" logs/debug.log
```

#### Просмотр промптов
```bash
# Статистика
grep "PROMPT_STATS" logs/debug.log

# Системные промпты
grep "PROMPT_SYSTEM" logs/debug.log

# Полные промпты (если FILE_LOG_LEVEL=FULL)
grep "PROMPT_FULL" logs/debug.log
```

#### Просмотр только сегодняшних логов
```bash
grep "$(date +%Y-%m-%d)" logs/debug.log
```

#### Просмотр вчерашних логов
```bash
# Автоматически подставляет вчерашнюю дату
cat logs/debug.log.$(date -v-1d +%Y-%m-%d)
```

#### Подсчет ошибок
```bash
grep -c "ERROR" logs/debug.log
```

#### Поиск по всем логам (текущим + архивным)
```bash
grep "текст_поиска" logs/debug.log*
```

### Docker logs (консольный вывод)

Docker logs показывают только ERROR+ сообщения и startup/shutdown информацию:

```bash
# Через docker-compose
docker-compose logs
docker-compose logs -f  # в реальном времени
docker-compose logs --tail=100  # последние 100 строк

# Или напрямую по имени контейнера
docker logs gpt-calendar-bot
docker logs -f gpt-calendar-bot  # в реальном времени
docker logs gpt-calendar-bot --tail=100  # последние 100 строк

# Проверить статус контейнера
docker ps
```

**💡 Совет:** Для полных логов (INFO, DEBUG, FULL) используйте файловые логи в `./logs/debug.log`, а не `docker logs`

## Устранение неполадок

### Логи не пишутся в файл

**Проблема:** После изменения `FILE_LOG_LEVEL` логи не появляются в `./logs/debug.log`.

**Решение:**
1. Перезапустите бота: `docker-compose restart`
2. Проверьте что директория `logs/` создана: `ls -la logs/`
3. Проверьте инициализацию логгера:
```bash
grep "Logger initialized" logs/debug.log | tail -1
```
4. Должна быть строка: `Logger initialized: FILE=INFO, TELEGRAM=DISABLED`

**Если директория `logs/` не существует:**
```bash
mkdir -p logs
docker-compose restart
```

### Логи не приходят в Telegram

**Проблема:** `TELEGRAM_LOG_LEVEL` установлен, но логи не приходят в чат.

**Решение:**
1. Проверьте что `TELEGRAM_LOG_LEVEL` не равен `DISABLED`
2. Проверьте что `ADMIN_CHAT` правильный (узнать ID: @userinfobot)
3. Проверьте что бот не заблокирован в чате
4. Перезапустите бота
5. Проверьте логи:
```bash
grep "Telegram logging handler enabled" logs/debug.log
```

### Слишком много логов

**Проблема:** Логи занимают много места.

**Решение:**
- Уменьшите `FILE_LOG_LEVEL` (например, с `DEBUG` на `INFO`)
- Логи автоматически ротируются каждые 24 часа и хранятся только за 2 суток
- Старые логи автоматически удаляются

### PROMPT_FULL не появляется

**Проблема:** В логах есть `PROMPT_SYSTEM` и `PROMPT_STATS`, но нет `PROMPT_FULL`.

**Причина:** `FILE_LOG_LEVEL` не установлен в `FULL`.

**Решение:**
```bash
# В .env
FILE_LOG_LEVEL=FULL

# Перезапустите бота
```

## Безопасность

⚠️ **Важно:**

1. **Защитите директорию `logs/`:**
   - Файлы содержат полную историю диалогов
   - Не коммитьте их в git (добавлено в `.gitignore`)
   - Ограничьте доступ на сервере: `chmod 700 logs/`

2. **ADMIN_CHAT:**
   - Используйте приватный чат
   - Не используйте публичные группы
   - Регулярно проверяйте кто имеет доступ

3. **Уровень FULL:**
   - Не используйте в production постоянно
   - Включайте только для отладки
   - Логи содержат ВСЮ историю диалогов

4. **Ротация логов:**
   - Старые логи автоматически удаляются через 24 часа (хранится 2 суток)
   - При необходимости архивируйте важные логи перед удалением

## Примеры использования

### Мониторинг в production

```bash
# .env
FILE_LOG_LEVEL=INFO
TELEGRAM_LOG_LEVEL=ERROR
```

Вы получите:
- ✅ В файле - все события для аналитики
- ✅ В Telegram - только ошибки для быстрого реагирования
- ✅ В консоли - traceback при критических ошибках

### Отладка проблем с LLM

```bash
# .env
FILE_LOG_LEVEL=FULL
TELEGRAM_LOG_LEVEL=DISABLED
```

Затем:
```bash
# Воспроизведите проблему
# Найдите полный промпт
grep "PROMPT_FULL_MESSAGE123456" logs/debug.log | tail -1

# Проверьте что отправляется в LLM
```

### Разработка новых функций

```bash
# .env
FILE_LOG_LEVEL=DEBUG
TELEGRAM_LOG_LEVEL=INFO
```

Вы получите:
- ✅ Подробные логи в файле для отладки
- ✅ Основные события в Telegram для удобства
- ✅ Быстрый доступ к логам без SSH
