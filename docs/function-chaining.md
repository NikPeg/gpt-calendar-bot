# Function Chaining (Цепочка вызовов функций)

## Что это такое?

Function Chaining - это возможность LLM делать несколько вызовов функций подряд в рамках одного запроса пользователя. Это позволяет модели сначала получить необходимую информацию, а затем выполнить действие на основе этой информации.

## Как это работает?

### Пример: Удаление события "Обед"

**До внедрения цепочки вызовов:**
```
Пользователь: "Удали событие Обед"
LLM: delete_calendar_event(event_id="Обед")  ❌ Неверно! "Обед" - это название, а не ID
Результат: Ошибка или ничего не удаляется
```

**После внедрения цепочки вызовов:**
```
Пользователь: "Удали событие Обед на завтра"
LLM: list_calendar_events(time_min="2026-01-05T00:00:00Z", time_max="2026-01-05T23:59:59Z")
Ответ: [
  {summary: "Встреча", id: "abc123"},
  {summary: "Обед", id: "lunch_id_456"}
]
LLM: delete_calendar_event(event_id="lunch_id_456")  ✅ Правильно!
Ответ: "Событие 'Обед' удалено успешно"
```

## Технические детали

### Изменения в коде

#### 1. Модификация `_process_llm_response` (services/llm_service.py)

Добавлен параметр `max_iterations` (по умолчанию 3) и цикл обработки:

```python
async def _process_llm_response(
    response: dict,
    chat_id: int,
    prompt: list[dict],
    functions: list[dict] | None,
    max_iterations: int = 3,  # Новый параметр
) -> str | None:
    iteration = 0
    current_response = response

    while iteration < max_iterations:
        # Проверяем tool_calls
        tool_calls = current_response.get("tool_calls")
        
        if not tool_calls:
            # Нет вызовов - возвращаем текст
            return current_response.get("content")
        
        # Выполняем функции и запрашиваем следующий ответ
        # ...
        iteration += 1
```

**Ключевое изменение:** `function_call="none"` → `function_call="auto"`

Это позволяет LLM делать дополнительные вызовы функций после получения результатов.

#### 2. Улучшенный системный промпт

Добавлены четкие инструкции для LLM:

```
КРИТИЧЕСКИ ВАЖНО для работы с календарем:
1. Для удаления или изменения события ВСЕГДА сначала используй list_calendar_events
2. Найди нужное событие в списке и возьми его реальный ID
3. Используй delete_calendar_event или update_calendar_event с полученным ID
4. НИКОГДА не используй название события как event_id
5. Ты можешь делать несколько вызовов функций подряд
```

### Защита от бесконечных циклов

1. **Ограничение итераций:** `max_iterations=3` (по умолчанию)
2. **Логирование:** Каждая итерация логируется с номером
3. **Предупреждения:** При достижении лимита выводится warning

## Использование

### В коде бота

Функция используется автоматически в `get_llm_response()`:

```python
response = await _process_llm_response(
    llm_response, 
    chat_id, 
    prompt_for_request, 
    CALENDAR_FUNCTIONS
)
```

## Преимущества

1. ✅ **Корректная работа удаления/изменения событий** - LLM теперь правильно получает ID

## Мониторинг и отладка

### Логи

Каждый вызов функции логируется с указанием итерации:

```
INFO: LLM123456: Calling function list_calendar_events with args: {...} (iteration 1/3)
INFO: LLM123456: Calling function delete_calendar_event with args: {...} (iteration 2/3)
```

При достижении лимита:

```
WARNING: LLM123456: Reached max iterations (3), returning last response
```

### Метрики

- Количество итераций на запрос
- Время выполнения каждой итерации
- Успешность цепочек вызовов

## Дальнейшие улучшения
